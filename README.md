# Регистрация на мероприятия

Организатор создаёт событие с лимитом мест и делится ссылкой. Участник регистрируется по email без аккаунта: подтверждает адрес кодом из письма и получает билет или место в листе ожидания. На главной — каталог событий с поиском и фильтрами. На входе организатор отмечает билеты, счётчик пришедших обновляется live. Почта уходит в Mailpit, реальной отправки нет.

Стек: Node 22, pnpm, Hono, PostgreSQL 17 через Drizzle, Vite + React, Mailpit. Один процесс отдаёт API и собранный фронт.

## Запуск

Нужен Docker с Compose v2.

```sh
docker compose up -d --build
docker compose exec api pnpm db:seed    # демо-данные; на непустой базе ничего не делает
docker compose exec api pnpm db:reset   # стереть базу, применить миграции, засеять заново
```

Приложение — <http://localhost:3000>, все письма — в Mailpit на <http://localhost:8025>. Сид печатает входы и ссылки на события.

Занятый порт сдвигается переменными `POSTGRES_PORT`, `MAILPIT_SMTP_PORT`, `MAILPIT_UI_PORT`, `API_PORT`. С другим `API_PORT` задайте и `PUBLIC_URL`, иначе ссылки в письмах поведут на порт 3000:

```sh
POSTGRES_PORT=5455 API_PORT=3001 PUBLIC_URL=http://localhost:3001 docker compose up -d --build
```

### Демо-данные

| Вход | Пароль | Роль |
|---|---|---|
| `demo@example.com` | `demo` | организатор, четыре события |
| `demo2@example.com` | `demo` | второй организатор, «Лекция»; события `demo` ему отвечают `404` |
| `support@example.com` | `support` | поддержка, одна заявка на исправление фамилии |

Участник входит без пароля: «Мои регистрации» в шапке → email → код из Mailpit. У `anna.ivanova@example.com` есть регистрации на все события `demo`. Ещё одну учётку поддержки создаёт `docker compose exec api pnpm admin:create <email>`.

Даты считаются от запуска сида:

| Событие | Где | Возраст | Состояние |
|---|---|---|---|
| «Митап: Postgres под нагрузкой» | онлайн | 12+ | 5 из 5 мест, трое в листе ожидания |
| «Воркшоп: формы на React без боли» | Новосибирск | 0+ | начало через ~5 ч; трое подтверждены трое суток назад, Глеб Попов — час назад |
| «Конференция «Бэкенд в Сибири»» | Новосибирск | 0+ | прошла двое суток назад, пришло 4 из 6 |
| «Ночной квиз 18+» | Москва | 18+ | пояс `Europe/Moscow` |
| «Лекция: как устроены очереди» (`demo2`) | Новосибирск | 0+ | 2 из 15 мест |

### Что проверить руками

- **Напоминание (R4).** Через минуту после сида в Mailpit приходят три письма «Скоро начало: Воркшоп…» — Анне, Борису и Вере. Глебу письма нет: он подтверждён меньше чем за сутки до начала, и напоминанием ему служит письмо о месте.
- **Каталог.** На `/` четыре предстоящих события. «Город: Москва» оставляет квиз, «Возраст: до 12+» его убирает, «Прошедшие» показывают «Конференцию». Фильтры лежат в адресе страницы, ссылку на выдачу можно отправить.
- **Вход участника.** Войдите как Анна. Сначала будет форма «Расскажите о себе», предзаполненная из последней регистрации. После «Сохранить» на «Текущих» — «Митап», «Воркшоп» и квиз, на «Прошедших» — «Конференция» со статусом «Пришли».
- **Регистрация без кода.** Под Анной с профилем откройте «Лекцию»: вместо формы одна кнопка, «Зарегистрироваться» сразу даёт «Место ваше» и письмо «Ваш билет». Новому адресу без профиля страница показывает форму.
- **Профиль (D-065).** На `/me` поменяйте Анне дату рождения так, чтобы на день квиза ей было меньше 18. Диалог «Регистрации будут отменены» перечислит квиз. «Сохранить и отменить» отменит регистрацию, место уйдёт первому из листа ожидания, а кнопка на странице квиза выключится.
- **Регистрация с кодом (R1).** Не входя как участник, зарегистрируйтесь на «Лекцию» или квиз с любым адресом: код и билет придут в Mailpit. Повтор с тем же email — «Вы уже зарегистрированы».
- **Лист ожидания и повышение (R2).** Регистрация на «Митап» ставит в лист ожидания. Чтобы освободить место, на странице «Митапа» раскройте «Уже регистрировались?», введите адрес Анны и откажитесь от участия. Егор Лебедев, первый в листе, получит «Для вас освободилось место» с билетом.
- **Чекин и live (R5).** Под `demo` откройте кабинет «Воркшопа» и экран чекина в двух вкладках. Коды билетов есть в письмах-напоминаниях. «Пришло» растёт без перезагрузки, повторный код — «Уже прошёл в ЧЧ:ММ».
- **Перенос (R6).** Измените время «Митапа»: письмо получат все восемь, включая троих из листа ожидания.
- **Минимальный возраст.** На квизе дата рождения младше 18 на день события — ошибка, код не отправляется.
- **Поддержка.** Под `support` примите заявку «Морозва → Морозова»: фамилия исправится, участнику уйдёт письмо.

Гонку за последнее место (R3) руками не воспроизвести, её проверяет тест.

## Разработка

Нужны Docker и Node ≥ 22.12 с pnpm (`corepack enable`).

```sh
pnpm install
pnpm dev   # Postgres и Mailpit из compose, API с перезапуском по правкам, Vite
```

`pnpm dev` берёт порты 5432, 1025, 8025, 3000 и 5173 и сдвигает занятые на следующий свободный. Адреса и команду сида с нужным `DATABASE_URL` он печатает при старте. Порт, заданный переменной (`POSTGRES_PORT`, `MAILPIT_SMTP_PORT`, `MAILPIT_UI_PORT`, `PORT`, `WEB_PORT`), не сдвигается: если он занят, запуск падает. Vite проксирует `/api`, ссылки в письмах ведут на него. После Ctrl+C контейнеры остаются (`docker compose stop`), база `app` общая с контейнером `api`.

## Тесты

```sh
docker compose up -d postgres mailpit
pnpm install
pnpm test                                               # Vitest, интеграционные тесты на настоящем Postgres
pnpm --filter @app/e2e exec playwright install chromium # один раз
pnpm e2e                                                # Playwright, приложение на :3100
pnpm typecheck && pnpm lint
```

Тесты заводят свои базы (по одной на воркер, `app_e2e` для e2e) и не трогают `app`, так что стенд может работать параллельно. Сдвинутые порты передаются через `TEST_DATABASE_URL`, `MAILPIT_URL`, `SMTP_PORT`, `E2E_PORT`.

CI (`.github/workflows/ci.yml`) на каждый push и PR запускает два job: `check` (типы, ESLint, `pnpm test`) и `e2e` (Playwright; при падении отчёт и трейсы сохраняются артефактом).

Тесты требований лежат в `apps/api/test/integration/requirements/`, имя каждого начинается с `R<n>:`. Каждый сначала закоммичен падающим и только потом получил реализацию (D-029). Номера `D-0xx` ведут в [`docs/DECISIONS.md`](docs/DECISIONS.md).

|---|---|---|---|---|
| R1 | Письмо с билетом; повтор на тот же email не создаёт второго места | Место и письмо ставятся в outbox одной транзакцией после верного кода. Частичный unique на (событие, email) среди неотменённых (D-007, D-011, D-013) | [`r1-ticket-and-repeat.test.ts`](apps/api/test/integration/requirements/r1-ticket-and-repeat.test.ts) | [`registration.spec.ts`](e2e/tests/registration.spec.ts) |
| R2 | Мест нет — в лист ожидания; отказ отдаёт место первому из листа с письмом | Распределение под блокировкой строки события, повышение в транзакции отказа (D-011, D-012) | [`r2-waitlist-promotion.test.ts`](apps/api/test/integration/requirements/r2-waitlist-promotion.test.ts) | [`cancel.spec.ts`](e2e/tests/cancel.spec.ts) |
| R3 | Двое на последнее место: место одному, второй в листе | Любое изменение мест начинается с `SELECT … FROM events … FOR UPDATE`. Тест — 10 параллельных подтверждений на 10 соединениях (D-011) | [`r3-last-seat-race.test.ts`](apps/api/test/integration/requirements/r3-last-seat-race.test.ts) | — |
| R4 | Ровно одно напоминание за сутки | Проход раз в минуту ставит письмо с уникальным ключом `reminder:<registration_id>:<reschedule_count>` (D-016, D-018, D-019) | [`r4-one-reminder.test.ts`](apps/api/test/integration/requirements/r4-one-reminder.test.ts) | — |
| R5 | Билет проходит чекин один раз; счётчик live | Условный `UPDATE … WHERE checked_in_at IS NULL`. Счётчик по SSE, триггер шлёт `NOTIFY` при коммите (D-020, D-021, D-022) | [`r5-checkin-live.test.ts`](apps/api/test/integration/requirements/r5-checkin-live.test.ts) | [`two-tabs.spec.ts`](e2e/tests/two-tabs.spec.ts) |
| R6 | Перенос — письмо всем участникам | Под блокировкой события письмо `rescheduled:<registration_id>:<reschedule_count>` каждой неотменённой регистрации, включая лист ожидания (D-016, D-017) | [`r6-reschedule.test.ts`](apps/api/test/integration/requirements/r6-reschedule.test.ts) | — |

Ещё три e2e: [`lookup.spec.ts`](e2e/tests/lookup.spec.ts) — «потерял письмо», вход в регистрацию по email и коду после начала события; [`catalog-signin.spec.ts`](e2e/tests/catalog-signin.spec.ts) — каталог, вход участника, регистрация без кода, «Мои регистрации»; [`profile.spec.ts`](e2e/tests/profile.spec.ts) — профиль, диалог конфликта возраста, выключенная кнопка на «18+», возврат к форме при `409 profile_required`.

**Ровно одно напоминание** — одно письмо на каждое время начала, если место получено больше чем за сутки до него. Иначе напоминанием служит письмо о месте, о повышении или о переносе внутрь последних суток. После переноса дальше чем на сутки напоминание придёт заново (D-016, D-019).

**Окно дубля.** Доставка at-least-once (D-013), повтор уходит с тем же `Message-ID`. Если процесс упал после того, как SMTP принял письмо, но до записи `sent_at`, через 2 минуты (аренда) письмо уйдёт ещё раз. `dedup_key` от этого не защищает.

**Один процесс API** (D-006, D-014). Rate limit считается в памяти: сбрасывается при рестарте, а несколько процессов считали бы каждый свой. Пинок отправки после коммита будит только свой процесс. Захват писем через `FOR UPDATE SKIP LOCKED` и ключ напоминания безопасны и при нескольких процессах.

## Состояние проекта

Собрано из [`docs/DEVLOG.md`](docs/DEVLOG.md) на 23.10.2026.

**Работает и покрыто тестами**
- R1–R6: интеграционные тесты на Postgres, шесть e2e в Chromium. CI (`check` и `e2e`) зелёный на `main` по #90 включительно. Локально: 218 тестов API в 28 файлах, 6 e2e, `typecheck` и `lint` чистые.
- Каталог на `/`: поиск, фильтры по времени, формату, городу, категории и возрасту, подгрузка страницами (D-056, D-061). API покрыт тестами, e2e проверяет фильтр по городу и бейдж «0+». «Показать ещё» не проверялось: в сиде четыре предстоящих события, а страница — 24.
- Вход участника по коду, «Мои регистрации», регистрация без кода, шкала возраста 0/6/12/16/18 (D-057–D-060). Не проверялись истёкшая сессия при отправке формы и состояния «Не отмечены на входе» и «Место не освободилось» на `/me`.
- Профиль и регистрация одной кнопкой (D-065), в том числе гонка правки профиля и регистрации. Не проверялись узкий экран (375 px), скринридер на диалоге и конфликт возраста при первом сохранении профиля.
- Регистрация с кодом, минимальный возраст, «потерял письмо», отказ по личной ссылке. Увеличение лимита отдаёт места листу ожидания, уменьшение оставляет билеты всем («сверх лимита»). После начала события работает только чекин.
- Организатор: события (удаление только без регистраций), кабинет с live-плашками и списком участников, чекин со снятием ошибочной отметки. Поддержка: заявки на исправление имени, фамилии и даты рождения, все события только на чтение.
- Rate limit, outbox с повторами и backoff, демо-сид. Пункты «если останется время» из SPEC §9 тоже сделаны.

**Урезано**
- В списке участников нет колонки «Код билета», поиска, «Показать ещё» и мобильных карточек из макета; «Снять отметку» стоит в ячейке времени прихода.
- Очередь поддержки обновляется опросом раз в 30 с, уведомлений нет.
- Кнопка подтверждения в диалогах всегда красная, даже у «Сохранить».
- R3 и R4 проверяют только интеграционные тесты: временем в браузере не управлять.

**Известные ограничения**
- Город и адрес — свободный текст: «СПб» и «Санкт-Петербург» в фильтре — разные города. Долг осознанный, по выбору пользователя (D-059).
- У онлайн-события нет поля для ссылки на трансляцию. Смена адреса письма не шлёт.
- Просроченные сессии участников не чистятся, срок проверяется при чтении (D-057).
- `X-Forwarded-For` учитывается только при `TRUST_PROXY=1`. Окно rate limit фиксированное. На `429` для SSE интерфейс молчит и переподключается через 3 с.
- Письма, не ушедшие за 10 попыток, видны только в логе и в `email_outbox`.
- QR-кода у билета нет (D-023).
- Нет теста на «потерял письмо», когда единственная регистрация email отменена.

**Вне рамок** (D-035): оплата, реальный почтовый провайдер, деплой, QR, сброс пароля, роль волонтёра, отмена события с письмами.
