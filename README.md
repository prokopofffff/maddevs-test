# Регистрация на мероприятия

Организатор создаёт событие с лимитом мест и делится ссылкой. Участник регистрируется по email без аккаунта: подтверждает адрес кодом из письма и получает место с билетом или встаёт в лист ожидания. На главной странице — каталог событий с поиском и фильтрами. На входе организатор отмечает билеты, счётчик пришедших обновляется live. Почта уходит в Mailpit, реальной отправки нет.

Стек: Node 22, pnpm, Hono, PostgreSQL 17 через Drizzle, Vite + React, Mailpit. Один процесс отдаёт API и собранный фронт.

## Запуск

Нужен Docker с Compose v2. Node и pnpm нужны только для тестов.

```sh
docker compose up -d --build
docker compose exec api pnpm db:seed
```

- Приложение: <http://localhost:3000> (на главной каталог событий)
- Mailpit (все письма): <http://localhost:8025>

База после `up` пустая: демо-данные появляются только после сида. Сид печатает входы и ссылки на страницы событий. На непустой базе он ничего не делает и подсказывает команду сброса:

```sh
docker compose exec api pnpm db:reset   # стереть базу, применить миграции, засеять заново
```

Если порт занят (например, 5432 — локальным Postgres), его можно сдвинуть переменной: `POSTGRES_PORT`, `MAILPIT_SMTP_PORT`, `MAILPIT_UI_PORT`, `API_PORT`. При другом `API_PORT` задайте и `PUBLIC_URL`, иначе ссылки в письмах будут вести на порт 3000:

```sh
POSTGRES_PORT=5455 API_PORT=3001 PUBLIC_URL=http://localhost:3001 docker compose up -d --build
```

### Демо-входы

| Вход | Пароль | Что есть |
|---|---|---|
| `demo@example.com` | `demo` | организатор, четыре события (ниже) |
| `demo2@example.com` | `demo` | второй организатор со своим событием («Лекция», ниже): события `demo` ему отвечают `404` |

Участнику пароль не нужен: вход на странице «Мои регистрации» (`/me`, ссылка в шапке) — email, затем код из письма. Код приходит в Mailpit. Для проверки подойдёт `anna.ivanova@example.com`: у неё есть регистрации на все события `demo`.

Все даты считаются от момента запуска сида. События (в каталоге видны все пять, в том числе «Лекция» второго организатора):

### Что проверить руками

- **Напоминание (R4).** Через минуту после сида в Mailpit приходят три письма «Скоро начало: Воркшоп…» для Анны, Бориса и Веры. Глебу письма нет: он подтверждён меньше чем за сутки до начала, и напоминанием ему служит письмо о месте.
- **Каталог.** Откройте `/` без входа: четыре предстоящих события. В фильтре «Город» выберите «Москва» — останется «Ночной квиз». Нажмите «Сбросить», в «Возраст» выберите «до 12+» — квиза нет, остальные три на месте. «Прошедшие» показывают «Конференцию». Поиск работает по названию и описанию, фильтры лежат в адресе страницы, так что ссылку на выдачу можно отправить.
- **Вход участника.** В шапке «Мои регистрации» → `anna.ivanova@example.com` → «Получить код» → код из письма «Код для входа» в Mailpit. После кода у Анны в сиде профиля ещё нет, поэтому сначала форма «Расскажите о себе», предзаполненная из последней регистрации: «Сохранить». Дальше на вкладке «Текущие» будут «Митап», «Воркшоп» и «Ночной квиз» («Место ваше»), на «Прошедших» — «Конференция» со статусом «Пришли». Повторный запрос кода для того же адреса раньше чем через минуту отказывает.
- **Регистрация без кода.** Войдите как `anna.ivanova@example.com` и сохраните профиль (см. выше), откройте «Лекцию»: вместо формы строка «Регистрируем: Анна Иванова, …» со ссылкой «Изменить» и одна кнопка. «Зарегистрироваться» сразу даёт «Место ваше», код подтверждения не просят. В Mailpit приходит только письмо «Ваш билет». Повторять на одной базе можно один раз на адрес: после этого «Лекция» покажет регистрацию Анны, а не кнопку. Новому адресу без профиля страница события показывает форму: регистрация по ней создаёт профиль.
- **Профиль и регистрация в один клик (D-065).** На `/me` над вкладками стоит «Анна Иванова · дата» и «Изменить». Поменяйте дату рождения на такую, при которой Анне меньше 18 на день «Ночного квиза»: диалог «Регистрации будут отменены» перечислит квиз («— с 18 лет»). «Не сохранять» оставляет всё как было; «Сохранить и отменить» отменяет регистрацию на квиз (она уходит в «Прошедшие» со статусом «Отменена», место получает первый из листа ожидания, если он есть, письма уходят), показывает «Отменены регистрации: …» и переписывает имя и дату в остальных предстоящих регистрациях. На странице «Ночного квиза» после этого кнопка «Зарегистрироваться» выключена с подсказкой «Регистрация с 18 лет на день события».
- **Регистрация (R1).** Откройте ссылку на «Лекцию» или «Ночной квиз» из вывода сида, не входя как участник, и зарегистрируйтесь с любым адресом. Код придёт в Mailpit, после него страница покажет «Место ваше», а письмо с билетом и личной ссылкой тоже придёт в Mailpit. Повторная регистрация того же email ответит «Вы уже зарегистрированы».
- **Лист ожидания и повышение (R2).** Регистрация на «Митап» ставит вас в лист ожидания. Чтобы освободить место, на странице «Митапа» раскройте «Уже регистрировались?» и введите `anna.ivanova@example.com`. Код придёт в Mailpit, по нему откроется регистрация Анны, там нажмите «Отказаться от участия». Егор Лебедев, первый в листе ожидания, получит письмо «Для вас освободилось место» с билетом.
- **Чекин и live (R5).** Под `demo` откройте кабинет «Воркшопа» в одной вкладке, а экран чекина — в другой. Коды билетов есть в письмах-напоминаниях. После отметки «Пришло» растёт в первой вкладке без перезагрузки. Тот же код повторно — «Уже прошёл в ЧЧ:ММ».
- **Перенос (R6).** Измените время «Митапа». Письмо о переносе придёт всем восьми: пяти подтверждённым и троим из листа ожидания.
- **Минимальный возраст.** На «Ночном квизе» дата рождения младше 18 лет на день события — ошибка, код не отправляется.
- **Поддержка.** Под `support` заявка Ксении «Морозва → Морозова»: «Принять» исправляет фамилию и шлёт письмо.
- **Прошедшее событие.** На странице «Конференции» регистрация закрыта, виден только вход «Уже регистрировались?».

Гонку за последнее место (R3) руками не воспроизвести — её проверяет тест.

## Разработка

Нужны Docker и Node ≥ 22.12 с pnpm (`corepack enable`).

```sh
pnpm install
pnpm dev       # Postgres и Mailpit из compose, API с перезапуском по правкам и Vite
```

`pnpm dev` (`scripts/dev.mjs`) поднимает контейнеры `postgres` и `mailpit`, ждёт их готовности и запускает API и Vite. Порты по умолчанию — 5432, 1025, 8025, 3000 и 5173. Если порт занят, берётся следующий свободный. Адреса и готовая команда сида печатаются при старте:

```
  Приложение: http://localhost:5174
  API:        http://localhost:3001
  Mailpit:    http://localhost:8025
  Postgres:   postgres://app:app@localhost:5433/app
  Сид:        DATABASE_URL=postgres://app:app@localhost:5433/app PUBLIC_URL=http://localhost:5174 pnpm db:seed
```

- Ссылки в письмах ведут на Vite; он проксирует `/api` на API.
- Уже работающие контейнеры переиспользуются вместе с их портами. После Ctrl+C они остаются, остановить: `docker compose stop`.
- Порт можно задать явно: `POSTGRES_PORT`, `MAILPIT_SMTP_PORT`, `MAILPIT_UI_PORT`, `PORT` (API), `WEB_PORT` (Vite). Заданный порт не сдвигается: если он занят, запуск падает.
- Контейнер `api` из compose и `pnpm dev` работают с одной базой `app`.

## Тесты

Тестам нужны Postgres и Mailpit из compose и Node ≥ 22.12 с pnpm (`corepack enable`).

```sh
docker compose up -d postgres mailpit
pnpm install
pnpm test                                               # Vitest, интеграционные тесты на настоящем Postgres
pnpm --filter @app/e2e exec playwright install chromium # один раз
pnpm e2e                                                # Playwright: собирает фронт и поднимает приложение на :3100
pnpm typecheck && pnpm lint
```

- `pnpm test` создаёт на сервере compose свою базу на каждый воркер. `pnpm e2e` пересоздаёт базу `app_e2e`. База приложения `app` не затрагивается ни тем, ни другим, так что стенд из `docker compose up` может работать параллельно.
- Без compose тесты сразу падают с подсказкой «Запустите `docker compose up -d`».
- Если порты сдвинуты, тестам их передают переменными: `TEST_DATABASE_URL=postgres://app:app@localhost:5455/postgres`, `MAILPIT_URL=http://localhost:8055`, `SMTP_PORT=1055`, `E2E_PORT`.

CI (`.github/workflows/ci.yml`) на каждый push и PR:
- job `check` — проверка типов, ESLint и `pnpm test` с Postgres и Mailpit в services;
- job `e2e` — Playwright, при падении отчёт и трейсы сохраняются артефактом.

Четвёртый e2e, [`lookup.spec.ts`](e2e/tests/lookup.spec.ts), проверяет случай «потерял письмо»: событие началось, а участник открывает свою регистрацию по email и коду. Пятый, [`catalog-signin.spec.ts`](e2e/tests/catalog-signin.spec.ts), идёт от каталога: фильтр по городу, бейдж «0+» на карточке, вход участника по коду из письма «Код для входа», регистрация без кода и «Мои регистрации». Шестой, [`profile.spec.ts`](e2e/tests/profile.spec.ts), проходит профиль: первое заполнение на `/me`, регистрация одной кнопкой, ошибку даты в будущем, диалог конфликта возраста («Не сохранять» и «Сохранить и отменить»), выключенную кнопку на «18+» и возврат к форме при `409 profile_required`.

**«Ровно одно напоминание»** — это ровно одно письмо на каждое время начала, если место получено больше чем за сутки до начала. Если место получено позже, роль напоминания играет письмо о месте или о повышении. Если событие перенесли внутрь последних суток, его играет письмо о переносе (D-016, D-019). После переноса на дату дальше суток напоминание приходит заново, по новой дате.

**Окно дубля.** Письма доставляются по схеме at-least-once (D-013): письмо из закоммиченной транзакции не теряется, а повтор уходит с тем же `Message-ID`. Дубль возможен в одном случае: процесс упал между моментом, когда SMTP принял письмо, и записью `sent_at`. Тогда после истечения аренды (2 мин) следующий проход отправит письмо ещё раз. Ключ `dedup_key` не даёт поставить второе напоминание в очередь, но от этого окна он не защищает.

**Ограничения одного процесса.** Стенд рассчитан на один процесс API (D-006, D-014):
- счётчики rate limit хранятся в памяти: при рестарте они сбрасываются, а при нескольких процессах каждый считает свой лимит;
- пинок отправки после коммита будит только свой процесс, остальные заберут письмо своим проходом раз в 2 с;
- захват писем через `FOR UPDATE SKIP LOCKED` и уникальный ключ напоминания безопасны и при нескольких процессах.

Одноразовыми сценариями Playwright (в репозиторий не вошли) один раз пройдены также вкладка «Прошедшие», выход из шапки и повторный заход на событие («Вы уже зарегистрированы»). Не проверялись: истёкшая сессия при отправке формы (ветка 401) и состояния «Не отмечены на входе» и «Место не освободилось» на `/me`. Раздел «Что проверить руками» ниже описывает вход, вкладки и регистрацию без кода, но не выход из шапки и не истёкшую сессию.
- Вход организатора и поддержки, «мои события», создание, правка и удаление события (удаление — только без регистраций).
- Регистрация с кодом подтверждения, минимальный возраст, вход «потерял письмо» по email и коду, отказ по личной ссылке.
- Лимит мест: увеличение отдаёт новые места листу ожидания, уменьшение ниже числа подтверждённых оставляет всем билеты («сверх лимита»).
- После начала события закрыты регистрация, отказ и повышение, чекин продолжает работать.
- Кабинет события с live-плашками и списком участников, экран чекина со снятием ошибочной отметки.
- Поддержка: заявки на исправление имени, фамилии и даты рождения, просмотр всех событий только на чтение.
- Rate limit на все запросы к API.
- Outbox с повторами и backoff, демо-сид.
- Пункты «если останется время» из SPEC §9 тоже сделаны: `429` на 11-й вход, backoff, истёкшая аренда и `failed_at` в outbox, возраст на границе дня рождения.

- Профиль участника (D-065): первое заполнение на `/me`, правка с диалогом отмены регистраций при конфликте возраста, регистрация на событие одной кнопкой с заранее выключенной кнопкой по возрасту, возврат к форме при `409 profile_required`. API покрыт интеграционными тестами (в том числе гонкой правки и регистрации), интерфейс — одним e2e (`profile.spec.ts`) в Chromium. Не проверялись: узкий экран (375 px) у новых форм, скринридер на диалоге, первое сохранение профиля, при котором сразу есть конфликт возраста (у гостевых регистраций того же email), и то, что тост «Отменены регистрации: …» держится три секунды и при длинном списке названий может пропасть раньше, чем его прочтут.

**Урезано или упрощено**
- В списке участников кабинета нет колонки «Код билета», поиска, «Показать ещё» и мобильных карточек из макета. На узком экране таблица прокручивается по горизонтали.
- «Снять отметку» стоит в ячейке «Время прихода», а не в отдельной колонке.
- Очередь поддержки обновляется опросом раз в 30 с, уведомлений о новых заявках нет. Время подачи заявки показано по часам браузера.
- Кнопка подтверждения в диалогах всегда красная, даже у «Сохранить» в диалоге «сверх лимита».
- Гонку (R3) и напоминания (R4) проверяют только интеграционные тесты: в браузере временем не управлять.

**Известные ограничения**
- Город и адрес события — свободный текст: справочника городов и геокодинга нет, адрес не проверяется. «СПб», «Санкт-Петербург» и «С.-Петербург» — три разных города в фильтре; фильтр сравнивает без учёта регистра, но не склеивает написания (D-059). Это долг по выбору пользователя, не недосмотр.
- У онлайн-события нет ссылки на трансляцию: организатор пишет её в описании, а в письмах у такого события просто «Онлайн».
- Смена адреса письма участникам не ставит: письмо уходит только при переносе времени.
- Сессия участника живёт 30 дней; просроченные строки `participant_sessions` не чистятся, срок проверяется при чтении (D-057).
- Один процесс API — см. выше. `X-Forwarded-For` учитывается только при `TRUST_PROXY=1`, и берётся последний адрес.
- Окно rate limit фиксированное: на границе минуты могут пройти два лимита подряд. На `429` для SSE интерфейс ничего не показывает: `EventSource` молча переподключается через 3 с.
- Неотправленные после 10 попыток письма видны только в логе и в таблице `email_outbox`.
- Когда процесс останавливается, открытые SSE-потоки закрываются, новый поток получает `503`, а через 5 с оставшиеся соединения обрываются.
- QR-кода у билета нет: ссылка на `localhost` с телефона всё равно не откроется (D-023).
- Нет отдельного теста на вход «потерял письмо», когда единственная регистрация этого email отменена.

**Вне рамок** (D-035, карта решений): оплата, реальный почтовый провайдер, деплой, QR, сброс пароля, роль волонтёра, отмена события с письмами.
